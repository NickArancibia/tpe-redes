\note{
  \guion{\oradorB}{1:00}
  \begin{itemize}
    \item Ansible configura servidores a partir de archivos que describen cómo tienen que quedar.
    \item Compara lo que hay con lo que pedimos y cambia solo la diferencia: correrlo dos veces no
      rompe nada. Un script, en cambio, repite siempre los mismos pasos.
    \item Menos errores humanos: nadie tipea los pasos a mano ni se saltea uno. Las recetas están en
      el repositorio y Ansible las ejecuta siempre igual, así que cualquiera del equipo obtiene el
      mismo resultado.
    \item Si preguntan: las recetas son playbooks. Ansible corre en el host y usa la API de Docker
      (\texttt{community.docker}) para crear los nodos y la de Kubernetes (\texttt{kubernetes.core})
      para desplegar, drenar y verificar.
  \end{itemize}
}

\note{
  \guion{\oradorB}{1:15}
  \begin{itemize}
    \item Kubernetes reparte la tienda entre varios servidores y la mantiene corriendo.
    \item Clic: si sacamos un servidor, levanta sus partes en los demás.
    \item K3s es Kubernetes completo en un solo programa, con pocos requisitos de memoria.
      Corre igual en una notebook, en servidores propios o en cualquier nube.
    \item Si preguntan: un nodo corre como server (control plane, API en 6443) y los demás como
      agents (workers), que se unen con la IP del server y un token que genera Ansible. K3s trae
      Traefik y ServiceLB, así que la tienda abre por el puerto 80 de cualquier nodo.
  \end{itemize}
}

  \end{itemize}

\note{
  \guion{\oradorC}{0:15}
  \begin{itemize}
    \item Si preguntan por los límites de la prueba: hay una sola copia de cada parte (al retirar
      un servidor la tienda puede tardar unos segundos), un solo servidor coordina a los demás y
      todo corre en una sola computadora. Se resuelven con réplicas + PodDisruptionBudget, tres

    \item Si preguntan por alternativas: kops arma todo con un comando, pero solo funciona en AWS y
      nos ata a ese proveedor y a sus precios. Kind, lo que se usa hoy, no deja sumar servidores.
      Minikube y k3d corren todo en una sola computadora.
    \item Si preguntan por VMs: cada nodo tarda minutos y pide al menos 2 GB de RAM, y en la nube
      hay que pagar tres VMs. Por eso los nodos de la demo son contenedores.
  \end{itemize}
